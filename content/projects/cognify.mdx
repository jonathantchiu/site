## The problem

Making flashcards from a lecture takes about an hour and none of that hour is
thinking. You already have the notes. You retype them into a different shape.
It is the step people skip in the week they need it most.

## What I built

Cognify takes notes you have already written and generates flashcards,
quizzes, and seven-day study plans from them. Notes can be grouped, so material
spread over several lectures generates as one set. Every generation is stored.
The latest one loads when you come back, and the full history stays available.

Flashcards flip, shuffle, and move with the keyboard. Quizzes are multiple
choice, reveal per question, and end with a score. Study plans are checkable
tasks, and the progress persists per note or group.

## How it works

A React frontend built with Vite talks to a FastAPI backend over a small REST
API. PostgreSQL 16 sits behind SQLAlchemy. The whole thing comes up with one
`docker compose up --build`.

The generation endpoints share one shape:
`POST /api/{notes|groups}/{id}/{kind}`, where `kind` is `flashcards`, `quiz`,
or `study-plan`. A new kind of study material needs a schema and a prompt. It
does not need a new route family.

Model output is validated before it is stored. A generation that fails
validation is retried once and then returns `502`. Nothing malformed reaches
the database, so a bad response from the model never becomes a broken flashcard
set someone has to delete by hand.

Tests run against in-memory SQLite with the OpenAI client mocked. The suite
needs no API key and no database.

## What broke

Early on, a malformed model response would persist and then crash the study
view on load. The crash surfaced one screen away from its cause, so it read
like a frontend rendering bug for a while.

Validating at the boundary fixed it. The response is parsed and checked against
a schema before it reaches the database. Bad data gets rejected where it enters
the system, and nothing downstream has to defend against it.
