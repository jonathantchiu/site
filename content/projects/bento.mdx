## The problem

Budgeting apps ask you to do the boring part first. You log expenses for a
week. Nothing on the screen changes, so you stop logging. I have quit three of
them that way.

I wanted a reason to open the app on a Tuesday when I spent nine dollars and
nothing else happened.

## What I built

Bento pairs a daily spending budget with a pet that reacts to it. Stay under
and the pet earns XP and treats. Go over enough times and it takes a vacation
until you recover. Logging an expense moves the daily allowance, and the pet
reacts to that same number.

It runs on iOS and Android with no network.

## How it works

The local SQLite database is the source of truth. Every read and write goes
through `expo-sqlite` first, so the app works with no account and no signal.
Supabase mirrors that data once you sign in, if you sign in.

State is split in two. Zustand holds in-memory UI state. Anything that has to
survive a restart goes to SQLite through a repository layer. Screens call
services, services call repos, and no component touches the database. That
boundary is what made the pet logic testable. Mood derivation is a pure
function of budget history, and it lives nowhere near a component.

Pet cosmetics are overlay sprites positioned by an anchor table keyed on pet,
mood, and item. The coordinates are fractions of the sprite's bounding box, so
the same numbers work at any render size.

## What broke

Equipped cosmetics did not render. The shop marked items owned and equipped,
the state was correct, and the pet showed nothing.

Item identity had two spellings. The anchor table keyed the cowboy hat as
`'cowboy hat'` with a space. The asset table keyed the same item as
`cowboy_hat`. Lookups against one table succeeded and the other returned
`undefined`, so the sprite resolved to a real image with no position and
rendered at zero size. It looked like a missing image file for longer than it
should have.

The fix was one canonical item id, with both the asset path and the anchor
derived from it. The two tables cannot drift apart now. This website normalizes
those ids on the way in for the same reason.
