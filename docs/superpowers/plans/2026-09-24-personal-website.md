# Personal Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a statically-exported personal site that showcases Jonathan Chiu's CS projects to a student audience, with a home page, a projects index, per-project detail pages, and an experience page.

**Architecture:** Next.js App Router with `output: 'export'`, styled with Tailwind using a palette sampled from the Bento app's artwork. Project content lives in MDX files parsed by a single module (`lib/projects.ts`) that every page reads through, so no page touches the filesystem directly. Motion is isolated in one `Reveal` component so the reduced-motion guard cannot be forgotten at a call site.

**Tech Stack:** Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 3.4, `next-mdx-remote` + `gray-matter` for MDX, Framer Motion for scroll reveals, Vitest + Testing Library for tests, `sharp` for the build-prep image pipeline.

**Spec:** `docs/superpowers/specs/2026-09-24-personal-website-design.md`

## Global Constraints

These apply to every task. They are copied from the spec; do not restate them per task, but do not violate them either.

- **Palette, exact values.** `--cream #FDFAF5`, `--sand #F2CEAB`, `--ink #2B1A0C`, `--orange #D88248`, `--orange-text #A34E1E`, `--muted #6B5238`.
- **`--orange` may never be used for text.** It measures 2.80:1 on cream and fails AA at every size. Fills, borders, and decoration only. Use `--orange-text` for accent type.
- **`--orange-text` on `--sand` is large-text only** (24px+, or 19px bold). It measures 3.87:1 there.
- **Body text is 17px minimum on phones.** Line height 1.6 on body, 1.25 on headings. Measure capped at 68 characters.
- **Tap targets are 44×44px minimum,** with at least 8px between adjacent targets.
- **No horizontal scroll at any width down to 320px.** Side gutters 16px minimum.
- **Every animation is wrapped in a `prefers-reduced-motion: reduce` guard** that disables transforms and transitions entirely.
- **No image over 200KB; hero images under 100KB.** All images converted to WebP before being committed.
- **Every image has explicit `width` and `height`.** Decorative sprites get `alt=""`.
- **One `<h1>` per page.** Semantic `<nav>`, `<main>`, `<footer>`, and a skip-to-content link.
- **Commit after every task.** Conventional Commits format.

This test encodes the two palette rules that are easy to break later. Write `__tests__/tokens.test.ts`:

```typescript
import { describe, it, expect } from 'vitest';
import { readFileSync } from 'node:fs';

function luminance(hex: string): number {
  const channels = [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16) / 255);
  const linear = channels.map((c) =>
    c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4,
  );
  return 0.2126 * linear[0] + 0.7152 * linear[1] + 0.0722 * linear[2];
}

function contrast(a: string, b: string): number {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);
}

function token(name: string): string {
  const css = readFileSync('app/globals.css', 'utf8');
  const match = css.match(new RegExp(`--${name}:\\s*(#[0-9A-Fa-f]{6})`));
  if (!match) throw new Error(`token --${name} not found in app/globals.css`);
  return match[1];
}

describe('palette', () => {
  it('body ink on cream passes AA for normal text', () => {
    expect(contrast(token('ink'), token('cream'))).toBeGreaterThanOrEqual(4.5);
  });

  it('accent text on cream passes AA for normal text', () => {
    expect(contrast(token('orange-text'), token('cream'))).toBeGreaterThanOrEqual(4.5);
  });

  it('muted text on sand passes AA for normal text', () => {
    expect(contrast(token('muted'), token('sand'))).toBeGreaterThanOrEqual(4.5);
  });

  it('decorative orange is documented as failing, so it is never used for text', () => {
    expect(contrast(token('orange'), token('cream'))).toBeLessThan(4.5);
  });
});
```

```javascript
// sizes the site actually serves, and writes them into public/.
//
// Run once: node scripts/prepare-assets.mjs
// Output is committed, so this is build-prep, not part of `next build`.

import { mkdir, writeFile } from 'node:fs/promises';
import { dirname } from 'node:path';
import sharp from 'sharp';

const RAW = 'https://raw.githubusercontent.com/jonathantchiu/bento-money/main';

const MOODS = ['happy', 'neutral', 'sad', 'sleep'];

// Bento's anchor table and its asset table disagree on key spelling
// ('cowboy hat' vs cowboy_hat). This site uses kebab-case ids, so the mapping
// from our id to Bento's filename is explicit here.
const COSMETICS = {
  'cowboy-hat': 'cowboy_hat',
  'chef-hat': 'chef-hat',
  'sunglasses': 'sunglasses',
  'sport-glasses': 'sport-glasses',
  'bughunter-toy': 'bughunterToy',
};

const SCREENSHOT_WIDTHS = [480, 768, 1200];

async function fetchBuffer(url) {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`${res.status} ${res.statusText} for ${url}`);
  return Buffer.from(await res.arrayBuffer());
}

async function write(path, buffer) {
  await mkdir(dirname(path), { recursive: true });
  await writeFile(path, buffer);
  console.log(`  wrote ${path} (${Math.round(buffer.length / 1024)}KB)`);
}

async function sprite(url, out, width = 512) {
  const buf = await fetchBuffer(url);
  const webp = await sharp(buf)
    .resize({ width, withoutEnlargement: true })
    .webp({ quality: 82 })
    .toBuffer();
  await write(out, webp);
}

async function main() {
  console.log('pets');
  for (const mood of MOODS) {
    await sprite(`${RAW}/NekoFinance/assets/pets/cat-${mood}.png`, `public/mascot/cat-${mood}.webp`);
  }

  console.log('cosmetics');
  for (const [id, source] of Object.entries(COSMETICS)) {
    await sprite(`${RAW}/NekoFinance/assets/shop/${source}.png`, `public/mascot/cosmetics/${id}.webp`);
  }

  console.log('done');
}

main().catch((err) => {
  console.error(err);
  process.exit(1);
});
```

- [ ] **Step 3: Write the implementation**

Write `lib/projects.ts`:

```typescript
import { readdirSync, readFileSync } from 'node:fs';
import { join } from 'node:path';
import matter from 'gray-matter';

const CONTENT_DIR = join(process.cwd(), 'content', 'projects');

export interface Project {
  slug: string;
  title: string;
  year: string;
  hook: string;
  stack: string[];
  repo: string;
  cover: string;
  featured: boolean;
  content: string;
}

function parse(filename: string): Project {
  const slug = filename.replace(/\.mdx$/, '');
  const raw = readFileSync(join(CONTENT_DIR, filename), 'utf8');
  const { data, content } = matter(raw);

  for (const field of ['title', 'year', 'hook', 'stack', 'repo', 'cover']) {
    if (data[field] === undefined) {
      throw new Error(`${filename}: missing required frontmatter field "${field}"`);
    }
  }

  return {
    slug,
    title: String(data.title),
    year: String(data.year),
    hook: String(data.hook),
    stack: data.stack as string[],
    repo: String(data.repo),
    cover: String(data.cover),
    featured: Boolean(data.featured),
    content,
  };
}

export function getAllProjects(): Project[] {
  return readdirSync(CONTENT_DIR)
    .filter((f) => f.endsWith('.mdx'))
    .map(parse)
    .sort((a, b) => b.year.localeCompare(a.year));
}

export function getFeaturedProjects(): Project[] {
  return getAllProjects().filter((p) => p.featured);
}

export function getProject(slug: string): Project | null {
  return getAllProjects().find((p) => p.slug === slug) ?? null;
}

export function getProjectSlugs(): string[] {
  return getAllProjects().map((p) => p.slug);
}
```

- [ ] **Step 1: Write the Bento page**

Write `content/projects/bento.mdx`:

```mdx
---
title: Bento
year: '2026'
hook: A budgeting app where staying under budget raises a virtual pet.
stack: ['React Native', 'Expo', 'TypeScript', 'SQLite', 'Supabase', 'Zustand']
repo: https://github.com/jonathantchiu/bento-money
cover: /projects/bento/home
featured: true
---

## The problem

Budgeting apps ask you to do the boring part first. You log expenses for a
week, nothing visible happens, and you stop. The data is correct and the habit
is dead.

I wanted the feedback loop to be short enough that opening the app felt worth
it on a day when nothing interesting happened financially.

## What I built

Bento pairs a daily spending budget with a pet that reacts to it. Stay under
budget and the pet earns XP and treats. Go over repeatedly and the pet takes a
vacation until you recover. The financial habit — log an expense, watch the
daily allowance — sits inside a loop cheap enough to come back to.

It runs on iOS and Android, fully offline.

## How it works

The local SQLite database is the source of truth, not a cache. Every read and
write goes through `expo-sqlite` first, so the app is fully usable with no
network and no account. Supabase is an optional mirror for signed-in users
rather than a dependency.

State is split deliberately: Zustand holds in-memory UI state, while anything
that must survive a restart goes to SQLite through a repository layer. Screens
never touch the database directly — they call services, which call repos. That
boundary is what made the pet logic testable, since mood derivation is a pure
function of budget history rather than something tangled into a component.

Pet cosmetics are overlay sprites positioned by an anchor table keyed on pet,
mood, and item, with coordinates stored as fractions of the sprite's bounding
box so the same numbers work at any render size.

## What broke

Equipped cosmetics did not render. The shop marked items as owned and equipped,
the state was correct, and nothing appeared on the pet.

The cause was two sources of truth for item identity. The anchor table keyed
the cowboy hat as `'cowboy hat'` with a space, while the asset table keyed the
same item as `cowboy_hat`. Lookups against one table succeeded and the other
returned `undefined`, so the sprite resolved to a real image with no position
and rendered at zero size. It looked like a missing asset and was actually a
missing key.

The fix was to make the item id one canonical string and derive both the asset
path and the anchor from it, so the two tables cannot drift apart again. The
same class of bug is why this website normalizes those ids on the way in.
```

```mdx
## The problem

The gap between having notes and being able to study them is annoying busywork.
Making flashcards from a lecture is mechanical, takes an hour, and is the step
people skip right before they need it most.

## What I built

Cognify takes notes you have already written and generates flashcards, quizzes,
and seven-day study plans from them. Notes can be grouped, so material spanning
several lectures generates as one set. Every generation is stored, the latest
reloads automatically, and full history stays available.

Flashcards have a flip view with shuffle and keyboard navigation. Quizzes are
multiple choice with per-question reveal and a final score. Study plans have
checkable tasks with progress that persists per note or group.

## How it works

A React frontend built with Vite talks to a FastAPI backend over a small REST
API, with PostgreSQL 16 behind SQLAlchemy for persistence. The whole thing
comes up with one `docker compose up --build`.

The generation endpoints follow one shape rather than three:
`POST /api/{notes|groups}/{id}/{kind}` where `kind` is `flashcards`, `quiz`, or
`study-plan`. Adding a new kind of study material means adding a schema and a
prompt, not a new route family.

Model output is validated before it is stored. A generation that fails
validation is retried once and then returns `502` rather than persisting
malformed data, so a bad response from the model never becomes a broken
flashcard set a user has to delete by hand.

Tests run against in-memory SQLite with the OpenAI client mocked, so the suite
needs no API key and no database.

## What broke

Early on, a malformed model response would persist and then crash the study
view on load — the failure surfaced one screen away from its cause, which made
it look like a frontend rendering bug.

Validating at the boundary fixed it. The response is parsed and checked against
a schema before it reaches the database, so invalid data is rejected at the
point it enters the system rather than discovered at the point it is read.
```

```tsx
import { motion, useReducedMotion } from 'framer-motion';
import type { ReactNode } from 'react';

export function Reveal({ children, delay = 0 }: { children: ReactNode; delay?: number }) {
  const reduced = useReducedMotion();

  if (reduced) return <>{children}</>;

  return (
    <motion.div
      initial={{ opacity: 0, y: 12 }}
      whileInView={{ opacity: 1, y: 0 }}
      viewport={{ once: true, margin: '-40px' }}
      transition={{ duration: 0.4, delay, ease: 'easeOut' }}
    >
      {children}
    </motion.div>
  );
}
```
